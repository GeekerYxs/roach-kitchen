## 结论 2：自愈产线这一轮补上的东西

| 现象（第 5、6 轮） | 改法 | 实跑验证 |
|---|---|---|
| 师傅掉线 / 窗口没了只能停摆等人 | `master_login.py`：line.toml `master_accounts` 指向账号文件，账号↔师傅关系自动试出来、缓存（只存名字）；runner 健康检查发现师傅不在或掉线 → 自动重登，全员回城，重跑这一步（每步最多 3 次） | 登录本身验证了（开批前 3 个师傅都是它登的）；本轮师傅没掉线，「掉线后自动重登」只有单元测试 |
| 一队停摆就永远停着 | 停摆后等 10 分钟从断点再试，最多 3 次（`park_wait` / `park_retries`） | 本轮没停摆过，只有单元测试 |
| 徒弟客户端切图卡死（第 5 轮 亿万34） | 恢复阶段（连续失败 3 次后）4 个徒弟全部关窗重登再回城，`recover_wait` 300 → 120 秒 | 本轮没走到恢复阶段 |
| 答题器明明在跑却报「没在运行」（每批都有） | 不再解析 `tasklist` 输出，改用 Windows Toolhelp 快照读进程名 | 下次启动总控生效 |
| 转职时 4 个徒弟进程同时写 state 文件：读到半个文件报错（b 队 23:42），还可能互相覆盖丢记录 | `bai_shi.mark` 加跨进程文件锁 + 写临时文件再原子替换；读到半个文件自动重读 | 之后整夜没再出现；测试：6 个进程同时各写 15 次，一条不丢 |
| 八阵图从 B 点回不到 A 点（c 队，卡 20 次） | A 点连续 3 趟走不到 → 把卡住的位置当新 A 点（离 B 至少 200 px） | 单元测试；c 队重跑时还是旧代码 |
| 逍遥古迹 (3840,2944) 卡住（b 队；第 4 轮同一个点） | 同一处卡 5 次就先往旁边 300 px 走一下（四个方向轮流）再寻路 | 单元测试 |
| 队里最后一个徒弟点 NPC 没对话框（树、水晶、通天花、倒花露 ×2、尸体，共 6 次；回城重跑都能过） | `team_npc`：点不出的人放到最后，等 15 秒再点；最后一轮前**原地关窗重登**再点。`dew_team`：花点不出就走开再回来，再不行留给下一圈 | 「等 15 秒再点」实跑过，**没用**；原地重登触发过 1 次，暴露了下一行的 bug |
| 原地重登的徒弟被判失败（人在地图 1000，`make_apprentices` 只认逍遥村） | 重登一律带 `--anywhere`：进了游戏就算成功（健康检查重登掉线徒弟也走这条路，之前野外掉线同样会误报） | 修好后手动重登 亿万60 成功 |
| 重登过的徒弟收不到邮件（邮件 id 只在出现时发给当时的窗口） | 重登前把旧窗口进程号记进 state（`tap_<pid>`），`mail_sell` 连旧窗口的抓包一起读 | 亿万60 补收 33 封 |
| 双倍到期后只剩加钙地瓜不会吃（第 5 轮 a 队） | 通天一 / 通天二巡逻中到期就原地吃一个地瓜继续 | **验证了**：02:48 亿万52「双倍时间到了，吃了 1 个加钙地瓜」 |
| 水晶 / 倒花露 时背包太满（亿万56 40/40） | 两步开头 `U space 4`（route 测试覆盖） | 下次启动总控生效（路线在启动时加载） |

### 还没解决的：最后一个徒弟点 NPC 没反应

规律：总是队里最后一个点 NPC 的徒弟，前面几个人刚在那儿逃出战斗；等 15 秒、走开再回来都没用，**回城后重跑一定能过**。
推测是服务器那边这个号的位置 / 状态和客户端不一致（没有证据确定）。现在的兜底是原地重登（下次能实测）和整步回城重跑（已经可靠，
每次多花 4–8 分钟）。如果原地重登也不行，下一步可以把「点不出的那个人单独回城再走过去」做成步内动作。
