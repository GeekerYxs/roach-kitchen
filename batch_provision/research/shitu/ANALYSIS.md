录制时间：2026-10-26 22:15–22:20。客户端版本 2.100。

参与角色：

| 角色 | char_id | 等级 | 身份 | pid |
|---|---|---|---|---|
| mm01 | 219510 (0x35976) | 31 | 徒弟，队长 | 30396 |
| 欧皇丨花花乀 | 166759 (0x28B67) | 70 | 师傅 | 23148 |

任务全程由用户手动操作，本工具只做录制。

原始数据都在本目录：
- `logs/net_<角色>.jsonl`：所有收发包，带明文 opcode 和 body

## 1. 一句话结论

- 考验任务本质上就是**普通的 NPC 对话**。
  - 题目和选项都放在 NPC 对话包 `0x4019` 里，是纯文字。
  - 回答就是普通的「选对话选项」请求 `0x0051`，内容只有**选项在屏幕上的位置（1..N）**。
- 封包里**没有题号，也没有答案 id**。
- 洗牌在服务器端做：每次出题，服务器把同一道题的选项随机排好序再发下来。服务器自己记得这次的顺序，收到位置号后按这个顺序判对错。

  好比一张考卷：服务器每次印卷子时把 A/B/C/D 打乱，学生只回答「我选第 3 个」，判卷的人手里有这张卷子的原样。
- 所以自动答题的做法是：**按题目文字查答案文字 → 在当前选项里找到这段文字的位置 → 发这个位置号**。

## 3. 封包格式

### 3.1 回答 = 选对话选项 `0x0051`（12 字节）【已确认】

```
<I 0> <I 选项位置 1..N> <I 0>
```

这和平时点 NPC 选菜单发的是同一个包（仓库里 `SelectNpcDialogEntry` 发的也是它）。

### 3.2 对话 `0x4019`（服务器 → 徒弟）【部分确认】

```
+0  u32  char_id（mm01 = 76590300）
+4  u32  npc_id（55010000 = 341）
+8  u8   01
+9  u8   选项数 + 1（主菜单 7 个选项 → 08；题目 4 个选项 → 05；答错页 1 个选项 → 02）
+10 2 字节（多半是 00 00，偶尔 04 00 / 00 fe / 00 20，意义不明）
+12 u16  正文长度（包括结尾的 0）
+14 正文（GBK）
之后  选项，每个是 <u16 长度><GBK 文字\0>，选项之间夹着 1–3 个字节
```

选项之间夹的这些字节：同一个主菜单发了 6 次，每次这些位置的值都不一样（`ff/00/06/0d`、`75`、`c5`、`2b`、`ce`…），所以判断是**服务器没初始化的内存**，不是答案 id。因为这些夹层字节长度不固定，包里的选项还没能稳定地按字节切开。

**以后读题和选项建议直接读内存里的对话框**（`world.read_dialog` / `parse_options`），不要解析封包。内存里的格式是：

```
#FFFFFF#2、什么什么大冒险2.0的人物背包左上角的飞行器使用的时间有什么限制？
#ABB5FC#[URL opt=1]不限制[/URL]
#ABB5FC#[URL opt=2]一小时只能使用两次[/URL]
#ABB5FC#[URL opt=3]一小时只能使用一次[/URL]
#ABB5FC#[URL opt=4]一小时只能使用三次[/URL]
```

这里的 `opt=N` 就是位置号，也就是 `0x0051` 要发的那个数。

### 3.3 洗牌的证据【已确认】

考验二做了两次，同一道题、同一个答案文字，两次的位置号不同，两次都判对：

| 题 | 第一次的选项顺序 → 发的 opt | 第二次的选项顺序 → 发的 opt | 答案 |
|---|---|---|---|
| 1 不是职业的 | 元素使/方士/**巫师**/猎人 → 3 | 元素使/方士/猎人/**巫师** → 4 | 巫师 |
| 2 飞行器 | **一次**/两次/不限制/三次 → 1 | 不限制/两次/**一次**/三次 → 3 | 一小时只能使用一次 |
| 3 黄色名字 | **高1~3级**/低7级以下/相同/低4~6级 → 1 | 低7级以下/低4~6级/**高1~3级**/相同 → 3 | 怪物等级比玩家等级高1~3级 |
| 4 平静海岸三区 | **二区与无尽平原一区**/二区与龙之都/夕阳草原与一区/无尽平原一区与龙之都 → 1 | **二区与无尽平原一区**/夕阳草原与一区/二区与龙之都/无尽平原一区与龙之都 → 1 | 平静海岸二区与无尽平原一区 |
| 5 死亡掉经验 | 20级/7级/5级/**11级** → 4 | 7级/5级/**11级**/20级 → 3 | 11级 |

由此可以确认：
- 发出去的只是位置号；
- 服务器按自己这次的顺序判对错；
- 包里没有别的答案标识（`0x0051` 的另外两个 u32 一直是 0）。

题目文字本身没有被打乱。题目前面的「1、」「2、」只是题序。

### 3.4 其他【已确认】

- **师傅这边**：考验期间师傅**收不到** `0x4019`，只在领奖时收到 `0x46ff`「获得了 13 道德」和 `0x40ee`。考验完全在徒弟这边进行。
- **任务表**：两边的任务树（P+0x1B94C / P+0x1B95C）在考验期间**都没有变化**，答题面板 ui+0x10C4 也一直是 0。也就是说，考验做到第几次只保存在服务器上，**客户端任务表里看不到**。要知道该做哪一次，只能看 NPC 开场白（「基本知识」/「知识」/「勇气和关心」）。
- **换队长**：用户中途试过「正式出师」，要求师傅当队长。过程中录到客户端发 `0x0035 <I0><I 对方 char_id>`，服务器两边都回 `0x4708 <I 新队长><I 旧队长><I a0000000>`，队伍名单顺序随之对调。所以 `0x0035` 应该就是「移交队长」（这一条只看到一次，算【推测→较可信】）。
- 「正式出师」由师傅当队长去点 NPC，选项 5 → 1。没有完成出师任务时回 `0x46ff`「需要完成出师任务」。
- 「出师任务」：徒弟 < 38 级时回「出师任务要求徒弟级别不小于三十八级」。

## 5. 以后怎么用程序自动答（设计草案）

全部沿用现有能力：
- 点 NPC 用 `ClickNpc(341)`（RVA 0x11180），或者直接发 `0x0050`；
- 选选项用 `SelectDialog(pos)`（RVA 0x11C70），或者发 `0x0051`；
- 读对话用 `world.read_dialog`。

```
前提：徒弟当队长，师傅在队里，两人都在 map 1 糊涂博士 (1398,1329) 附近，徒弟背包至少留 2 个空位
1. ClickNpc(341)，等对话框出现，内容含「师徒任务」→ 选「师徒任务」那一项（按文字找位置，现在是 4）
2. 选「考验任务」(1)
3. 看开场白：含「勇气和关心」→ 第三次考验，需要打地头蛇，自动答题到此停下；含「考验」和「准备好了」→ 选「准备好了」
4. 循环：读对话 → 正文匹配 /^\d+、(.*)$/ → 用题目文字查题库 → 在 options 里找到答案文字对应的 opt → Select(opt)
       → 等对话内容变化（实测服务器约 50 ms 回包；内存里对话 ~0.2 s 内更新）
   - 正文含「很可惜，你答错了」→ 记下这题这个选项是错的，选「好的」，从第 1 步重来（实测重来没有惩罚）
   - 正文含「回答得不错」→ 选奖励（第一次：接受奖励；第二次：按职业选护甲）
   - 题库里查不到 → 停下报告；或者用排除法：选一个还没试过的选项，错了就重来，把结果记进题库
5. 领奖后可以用金币变化 / 0x46ff「获得了…」消息确认成功
```

要点：
- **按文字匹配，不要按位置号**。位置每次都会变，只有文字是稳定的。
- 匹配前把颜色码（`#RRGGBB#`）和题号「N、」去掉。答案文字要整句完全一致，因为有几道题的选项只差几个字，比如「一小时只能使用一次/两次/三次」。
- 不能靠任务表判断进度，要靠 NPC 开场白。
- 第三次考验（打地头蛇）不是答题。地头蛇是 NPC 1172，在 map 750 (4014,7869)，数据来自 `NPCDirection.csv`，【推测】它是一个点了就开战的 NPC。打法和地点需要再录一次。

## 8. 程序自动答题实测（2026-10-26 22:27–22:30）【已确认】

`trial_run.py` 让 mm02（30 级）、mm03、mm04（31 级）依次以队长身份和欧皇组队，全程只通过内存读取和调用游戏函数完成，**没有点 UI**：

## 9. 第三次考验（勇气和关心 = 带徒弟打地头蛇）【已确认】2026-10-26 23:21–23:28

前置条件：
- 欧皇（师傅，队长）+ mm01–mm04 组队，每个人都接了任务 224「遗忘洞穴的恐慌」（28 级才能接）；

### 14.3 删除徒弟角色（`delete_apprentices.py`）

步骤和 factory/delete.py 一样，只是没有料理线数据库那道检查：
1. 关掉游戏内的窗口；
2. 重新登录到选角界面；
3. 按 ID 加名字核对是哪个角色；
4. 检查 +0x60 保护标志、客户端自己的删除标志，以及发包用的连接；
5. 发 `0x0003`，等 `0x4004`。

3 个角色都是 result=0，服务器说 72 小时后释放槽位。

**注意**：这次登录后，三个账号的选角列表里都**只有一个角色**（十万N 自己，排在第 1 槽）。今天 00:26 建号时，第 1 槽还是 mm01–mm03。所以 mm01–mm03 在这之前已经不在了，不是这个脚本删的，脚本只删了指定 ID 的角色。
