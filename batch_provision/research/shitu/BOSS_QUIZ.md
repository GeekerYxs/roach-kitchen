# 迷宫 boss「开打」时弹的答题（0x46f5）

现状（2026-10-30，客户端 2.101）：题号 2601～3000 共 400 题已经全部收集，答案全部推算出来并且在用。
这份文件只写**现在怎么运作**；早期实验记录、2.100 的旧地址、商业辅助的分析在 git 历史里（2026-10-30 之前的版本）。

- 自动答：`大冒险2_自动答题器_原生无感关窗版`（启动答题器.exe + DLL），说明见它的 `src/README.md`。
- 兜底：师徒脚本 `dts.py` / `scorpion_king.py` 调 `boss_quiz.solve`，先等答题器 4 秒，面板还开着就自己答（同一份题库）。
- 题目采集记录：[`docs/BOSS_QUESTION_COLLECTION_20261030.md`](../../../docs/BOSS_QUESTION_COLLECTION_20261030.md)。

标记：【已确认】= 有封包 / 内存 / 反汇编 / 实测证据；【推测】= 合理但没直接验证。

## 1. 结论

| | 战斗里的题 | **boss 开打时的题** |
|---|---|---|
| 出题 S→C | `0x46f4` | **`0x46f5`** |
| 答题 C→S | `0x1f04` | **`0x1f05`** |
| 结果 S→C | `0x46ff`「测试通过！」+「获得了100金币」 | 同左 |
| 内存面板 | `[ui+0x12F4]` 控件 `Question` | **`[ui+0x12F8]` 控件 `QuestionOnMap`** |
| 题库 | `data/bank.json`（编进 DLL） | `data/boss_bank.tsv`（400 题） |

- 点「开打」后服务器不进战斗，而是出题；**答对以后要重新点 boss、再选「开打」**才真正开打。【已确认】
- 没答之前，这个号点任何 NPC 服务器都不回；答完马上恢复。没有超时（挂 4 小时再答也通过）。【已确认】
- **答错 = 被服务器踢下线**。师徒脚本用 `boss_quiz.kicked()` 识别，交给产线重登后整步重跑。【已确认】

## 2. 题库和答案规律【已确认】

- 题号是固定题库编号，**2601～3000 共 400 题**，同一题号的题目、选项、顺序每次都一样（3,838 次观察，每题号只有一个版本）。
- 每题 4 个选项：1 个正确，3 个干扰项来自另一类（古书、古人、诸子、名句）。
- **正确下标 = (题号 − 2601) ÷ 100 取整**：2601～2700 第 1 项，2701～2800 第 2 项，2801～2900 第 3 项，2901～3000 第 4 项。
  证据：服务器认可过的 37 道全部符合；400 题在这个位置上都是唯一和题目沾边的选项。
- 有几道「正确答案」按常识是错的（2934「2、3、5、7、14、13」、2743「鸡蛋煮熟是物理变化」），以服务器为准。
- 题目相同的不同题号（如 2776 / 2866 都问最大的半岛）答案位置不同，**按题号查，按答案文字找选项**。

题库文件（`大冒险2_自动答题器_原生无感关窗版/data/`，由 `src/tools/gen_boss_bank.py` 从采集数据生成）：

| 文件 | 内容 |
|---|---|
| `boss_questions_0x46f5_20261030.json` | 原始采集数据：400 个题号的题目和选项（没有答案） |
| `boss_bank.tsv` | 题号、答案文字、下标、题目、来源（实测 / 推算）。答题器答对推算的题后自动改成「实测」 |
| `boss_decoys.txt` | 400 题的全部错误选项。只在遇到题库里没有的新题号时用来排除（实测 395/400 能排到只剩正确项） |

题目以后如有变化：更新 JSON → 跑 `gen_boss_bank.py`（和实测冲突会报错、不写文件）。

## 3. 封包格式【已确认】

所有整数小端；字符串是「1 字节长度 + GBK」，没有结尾 0。

**出题 S→C `0x46f5`**

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 4 | 自己的 char_id |
| 4 | 4 | 后面还有多少字节（= 总长 − 8） |
| 8 | 1 | 类型，样本里全是 1（文字题【推测】） |
| 9 | 4 | **题号** |
| 13 | 1+L | 题目 |
| … | 1 | 选项个数，**全是 5**（第 5 个是空字符串，不用管） |
| … | | 每个选项「1 字节长度 + GBK」，自带编号「1、」，比较前去掉 |

战斗题 `0x46f4` 一样，只是开头没有 char_id、选项个数 4。

**答题 C→S `0x1f05`（13 字节）**：`00000000 05000000 <题号 4> <下标 1，0 开始>`。前 8 字节固定，含义不明，照抄。
战斗题 `0x1f04` 是去掉开头 4 个 0 的 9 字节。没有 token、时间戳、校验。

## 4. 内存（2.101）【已确认】

```
ui            = [base + world.UI_RVA]     （provisioner/world.py）
QuestionOnMap = [ui + 0x12F8]             boss 题；战斗题 Question = [ui + 0x12F4]
text          = [[QuestionOnMap + 0x3FC] + 0x108]   char*，GBK，以 0 结尾
```

| 面板偏移 | 含义 |
|---|---|
| +0x1C | 1 = 面板开着（判断有没有题要看它，面板关后文字有时还留着） |
| +0x104 | CloseDialog 的 parent |
| +0x3D4 | 题号 |
| +0x3DC | 选中的下标（0 开始，-1 = 没选） |
| +0x3E4 | 1 = 发 0x1f05（boss 面板），0 = 发 0x1f04 |

面板文字格式：第 1 行题目，之后每个 `[URL]…[/URL]` 是一个选项，顺序就是下标顺序（颜色码 `#RRGGBB#` 要去掉）：

```
#FFFFFF#世界上最大的半岛是什么？\n\n#ABB5FC#[URL]1、《诗经》[/URL]\n … #ABB5FC#[URL][/URL]\n
```

**作答 = 和手动点一样**：写 +0x3DC = 下标 → `thiscall RVA 0x2293A0(面板)`（客户端自己发 0x1f05）→
`CloseDialog RVA 0x3D1B50([面板+0x104], 面板, 0)`。地址全在答题器 `src/dll/game_addrs.h`，Python 兜底在 `boss_quiz.py` 顶部。
