用户手动点「开打」、手动答题，我这边只读、只录（`monitor.py --new 伏地魔1` + 已经挂着的录包 DLL），没发任何包。

## 0. 一句话结论

- 游戏里有**两套**弹窗答题，长得一样，是同一个界面类的两个实例：

  | | 战斗里的题 | **地图上的题（boss 开打时）** |
  |---|---|---|
  | 出题 S→C | `0x46f4` | **`0x46f5`** |
  | 答题 C→S | `0x1f04` | **`0x1f05`** |
  | 结果 S→C | `0x46ff`「测试通过！」+「获得了100金币」 | 同左 |
  | 内存面板 | `[ui+0x10C4]`，控件名 **`Question`** | **`[ui+0x10C8]`，控件名 `QuestionOnMap`** |
  | 谁在答 | 现有答题器 quizbot_v2，16–47 ms 自动答 | 没人，只能手动 |

  打个比方：同一种「答题卡」印了两张，一张放在战斗场景里，一张放在地图上。答题器只盯着第一张，所以第二张没人管。
- **题和选项都能从封包读，也能从内存读**（第 3 节）。
- **答案按位置发，0 开始**（选第 3 项就发 `02`），同时回传服务器给的题号。没有别的 token。
- **答题时根本没进战斗**：点「开打」的请求被服务器换成了出题；答对以后要**重新点 boss、重新选「开打」**才会真正开打。

## 2. 封包格式

### 2.1 出题 S→C `0x46f5`【已确认，10 个样本】

所有整数小端。字符串是「1 字节长度 + GBK 文字」，**没有结尾 0**。

| 偏移 | 长度 | 含义 | 这次的值 |
|---|---|---|---|
| 0 | 4 | 自己的 char_id | `c60a0300` = 199366 |
| 4 | 4 | 后面还有多少字节（= 总长 − 8） | `54000000` = 84 |
| 8 | 1 | 类型，样本里全是 1 | `01` |
| 9 | 4 | **题号 qid** | `320b0000` = 2866 |
| 13 | 1 | 题目长度 L | `18` = 24 |
| 14 | L | 题目 GBK | 世界上最大的半岛是什么？ |
| 14+L | 1 | 选项个数 N，**样本里全是 5** | `05` |
| … | | N 个选项，每个「1 字节长度 + GBK」 | `0b`「1、《诗经》」`0d`「2、《全唐诗》」`0d`「3、阿拉伯半岛」`0b`「4、《诗品》」`00`（第 5 个是空的） |

- 选项文字自己带编号「1、」「2、」…，答题时要去掉前缀再比较。
- 第 5 个选项永远是空字符串，界面里会画成一个空的 `[URL][/URL]`，不用管。【已确认】
- 类型字节 1 =「文字题」【推测】。界面里还有一个看图题的模板（第 3.3 节），也许类型 ≠ 1 时是看图题，没见过样本。

### 2.2 对比：战斗里的题 S→C `0x46f4`【已确认，40 多个样本】

和 0x46f5 一样，只是**开头少了 char_id**，选项个数是 4（没有空的第 5 项）：

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 4 | 后面还有多少字节（= 总长 − 4） |
| 4 | 1 | 类型 = 1 |
| 5 | 4 | 题号（样本里 1–20） |
| 9 | 1+L | 题目 |
| … | 1 | 选项个数 = 4 |
| … | | 4 个选项 |

### 2.3 答题 C→S `0x1f05`（13 字节）【已确认，10 个样本】

| 偏移 | 长度 | 含义 | 这次的值 |
|---|---|---|---|
| 0 | 4 | 全是 0 | `00000000` |
| 4 | 4 | 全是 5 | `05000000` |
| 8 | 4 | **题号，原样回传 0x46f5 里的 qid** | `320b0000` = 2866 |
| 12 | 1 | **选的选项，0 开始的下标**（选第 1 项发 `00`，第 4 项发 `03`） | `02` = 第 3 项 |

- 10 个样本里前 8 字节一模一样；它们是什么意思不知道【推测：固定的子类型 / 保留字段】，照抄就行。
- 战斗题 `0x1f04` 是 9 字节：`05000000 <qid 4 字节> <下标 1 字节>`，就是 0x1f05 去掉开头 4 个 0。【已确认】
- **按位置答，不是按选项 id 答**。选项本身没有 id。【已确认】
- 没有别的 token、时间戳、校验。【已确认：反汇编里只写了 qid 和下标，见 3.2】

### 2.4 结果 S→C `0x46ff`

普通的系统消息包：`<char_id 4><长度 4><GBK 文字>\0`。
- 答对：「测试通过！」，约 100 ms 后再来一条「获得了#00FF00#100#FFF692#金币」，同时 `0x40e5` 更新金币。【已确认】
- **答错**：10 个样本全是答对的，**没录到过答错**。服务器回什么、会不会再出一题，不知道。
- **超时**：没看到超时。百万2 的题（qid 2703）05:42 弹出、09:50 才答，隔了 4 小时 7 分钟，服务器照样回「测试通过！」。【已确认】
  但没答的这段时间里，这个号点任何 NPC 服务器都不回（第 2 轮报告 `notes/round2-report.md`）。【已确认】

## 3. 内存

### 3.1 两个面板在哪【已确认】

```
ui      = [base + 0x6959E8]          (world.UI_RVA)
Question      = [ui + 0x10C4]        战斗题 0x46f4
QuestionOnMap = [ui + 0x10C8]        boss 题 0x46f5
```

两个对象 vtable 一样（RVA 0x4fd5cc），对象 +0x3C 处就是控件名字符串 `"Question"` / `"QuestionOnMap"`。

面板字段（伏地魔1 答完以后读的，值还留着）：

| 偏移 | 含义 | 伏地魔1 现在的值 |
|---|---|---|
| +0x1C | 显示中（1 = 面板开着）| 0 |
| +0x1CC | → 子控件 `QOnlyReadText`（题目 + 选项的富文本）。两个面板都是这里（商业辅助也读这里） | |
| +0x174 | QuestionOnMap 上恰好也指向 QOnlyReadText，Question 面板上是 0，**不要用** | |
| +0x178 | → 发包用的对象（为 0 时不发） | |
| +0x17C | → 子控件 `Ok`（确认按钮） | |
| +0x180 | → 子控件 `Tip`（看图题说明，固定文字） | |
| +0x18C | → 子控件 `QI`（看图题的图）【推测】 | |
| +0x1A4 | **题号 qid** | 2866 |
| +0x1AC | **当前选中的下标**（0 开始，-1 = 还没选） | 2 |
| +0x1B4 | **1 = 发 0x1f05，0 = 发 0x1f04** | 1（Question 面板是 0） |

- +0x1C 是不是「显示中」：在 `Question` 面板上已确认（world.py 一直这么用，0x46f4 弹出时变 1）；在 `QuestionOnMap` 上是**同一个类**，所以【推测】也一样，**还没在 0x46f5 弹着的时候实测过**。
- 这也解释了以前的现象：monitor 和 `world.read_state` 的 `question` / `verification` 只看 `ui+0x10C4`，所以 0x46f5 弹出时（包括百万2 那道挂了 4 小时的）**一直是 false**。monitor 里的 `text_1ac` 读的其实是「选中的下标」，不是文字，所以永远是 null。

### 3.2 题目文字在哪【已确认】

```
text = [[QuestionOnMap + 0x1CC] + 0x108]     → char*，GBK，以 0 结尾（Question 面板同理）
```

伏地魔1 现在读出来是（客户端把 0x46f5 改写成了和 NPC 对话一样的格式）：

```
#FFFFFF#世界上最大的半岛是什么？\n\n
#ABB5FC#[URL]1、《诗经》[/URL]\n
#ABB5FC#[URL]2、《全唐诗》[/URL]\n
#ABB5FC#[URL]3、阿拉伯半岛[/URL]\n
#ABB5FC#[URL]4、《诗品》[/URL]\n
#ABB5FC#[URL][/URL]\n
```

- 第 1 行是题目，后面每个 `[URL]…[/URL]` 是一个选项，顺序就是下标顺序。
- 面板关掉以后文字**有时**还留着（伏地魔1 留着；伏地魔2 的已经清空、qid 也变回 0），所以**判断有没有题要看 +0x1C，不能看有没有文字**。

现成的只读小工具：`boss_quiz_peek.py`（这次新加的，没提交）

```
python -X utf8 boss_quiz_peek.py 伏地魔1                 # 读一次
python -X utf8 boss_quiz_peek.py --watch 伏地魔1 伏地魔2  # 一直看，变了就打印一行
```

### 3.3 发答案的客户端函数【已确认：反汇编】

RVA **0x224330**（thiscall，ecx = 面板对象）就是点「确认」后发答案的函数，两种题共用：

```
if [panel+0x178] == 0: 不发
写 4 字节 [panel+0x1A4]（题号）
写 1 字节 [panel+0x1AC]（选中的下标）
if [panel+0x1B4] != 0: 发 0x1f05   (调用点 0x22444b，返回地址 0x224450)
else:                  发 0x1f04   (调用点 0x2244f0，返回地址 0x2244f5)
发完 [panel+0x1B0] = 0
```

录包里 0x1f05 的 `caller_rva` 是 `0x224450`、0x1f04 是 `0x2244f5`，和这里对得上。
现有答题器发 0x1f04 时 caller_rva 也是 `0x2244f5`：它就是「把 +0x1AC 设好、再调 0x224330」【已确认：源码 `invoke_native_dismiss_internal` 和仓库 DLL 反汇编，2.98 时这个函数在 0x220950】。换成 `QuestionOnMap` 面板调一次，就会发 0x1f05【推测，没试过】。

## 4. 战斗在答题时是什么状态【已确认】

- **没有进战斗**。点「开打」（0x0051）以后服务器没回 `0x4100`（进战斗），而是回了 `0x46f5`。内存 battle=false、busy=false，对话框关闭。

## 5b. 商业辅助 mxbl3.106 和仓库答题器为什么都不答 boss 题（2026-10-27 静态分析，没运行它）

看的文件：`C:\Users\Y\Downloads\Compressed\mxbl1027\mxbl3.106 - 副本\mxbl_newdll_2.dll`（没加壳，只用 capstone 读文件反汇编）。

### 商业辅助是怎么答题的【已确认：反汇编】

1. **找题**（DLL 函数 0x100107f0）：偏移不是写死的，是「控制端传来的数 × 50」再加 0x318 / 0x31C，算出来正好是 `ui+0x10C4` 和 `ui+0x10C8`。所以直接搜常量 0x10C8 搜不到。
   - 先看 `[ui+0x10C4]+0x1C`（Question 开着吗），开着就读 `[[面板+0x1CC]+0x108]` 的题目文字；
   - 不开再看 `[ui+0x10C8]+0x1C`（QuestionOnMap），开着也读它的文字。
   - 也就是说：**它是看得到 boss 题的**。
2. **配题**（0x10010970）：拿题目文字在内置表里逐条做「包含」匹配（题目里含关键词 → 在选项里找含答案关键词的那项）。表里 **202 条**，每条 12 字节 `{0, 题目关键词 char*, 答案关键词 char*}`，在 DLL 文件偏移 0x90090。还有算术题（「2+3=」「肆拾贰」）。
3. **作答**：把下标写进面板 +0x1AC → 调游戏 RVA **0x224330**（发答案）→ 调 RVA 0x3c7e50（关窗，参数是面板 +0x104）。
   **但这一步写死了 `[ui+0x10C4]`**（`mov edi,[edi+0x10c4]`，DLL 0x10010a0a / 0x10010a2c），不管题是从哪个面板读到的。

### 为什么它答不了 boss 题

- **题库里一道 boss 题都没有**：202 条拿去比，录到的 19 道战斗题（0x46f4）**19/19 全中**，9 道 boss 题（0x46f5）**0/9**。boss 题的干扰项（诗经、孙子兵法、关汉卿…）在 DLL 里也一个都没有。【已确认】
  boss 题号从 2616 到 2934，题库至少有三百多道；战斗题号只有 1–20。所以「几百道题」指的是这 202 条，覆盖的是战斗题和一批常识题，不是 boss 题库。
- 就算配上了，它也会把答案写到战斗题面板上、发 0x1f04 带错的题号【推测：照反汇编推出来的，没运行】。
- 这 202 条**我们仓库 `大冒险2_自动答题器_原生无感关窗版/data/bank.json` 里已经全有了**（202/202 能在 bank.json 的题目里找到），所以它的题库没有新东西可抽。

### 仓库答题器为什么不答【已确认】

源码在 `D:\Codes\Gemini_Prj\smsm2_game\quiz_dismiss_bot\`（仓库里只有编译好的 DLL，2.100 版只改了地址数字）：
- `dll/quiz_protocol.h`：只定义了 `OP_QUESTION = 0x46F4`、`OP_ANSWER = 0x1F04`；
- `dll/quizbot_hook.cpp` 第 747 行：收包时只认 `op == 0x46F4`，**0x46F5 直接放过去，控制器根本不知道有题**；
- 关窗函数 `invoke_native_dismiss_internal` 只读 `ui+0x10c4`。
  仓库 DLL 反汇编也一样：只有一处 `cmp dx, 0x46f4`，只有一处 `[edx+0x10c4]`。

   - 发包：`build_answer` 加一个 0x1F05 版本，明文 13 字节 `00000000 05000000 <qid> <下标>`；
   - 走游戏自己的函数（和商业辅助一样）：`p=[ui+0x10C8]`，确认 `p+0x1B4==1`、`p+0x1C!=0`，写 `p+0x1AC=下标`，`thiscall 0x224330(p)`，再 `CloseDialog([p+0x104], p, 0)`。
3. **选答案**：先查「qid → 下标」表（第 5 节 10 条）；查不到就用「排除干扰项」（错误项都是古书 / 古人 / 名句，正确项唯一和题目沾边）；答对（0x46FF「测试通过！」）后把 qid 和下标存进表。
4. 注意：**还没见过答错是什么后果**，第一次上线建议只对表里有的题自动答，表里没有的先弹给人确认。
