# 满爆方士带四人（或宠）升级到70

这是一个独立的无任务练级项目：队长是满爆方士，带四个队员；常规配置由队长与其魔法宠物负责战斗，队员不攻击。目标是按地图等级区间持续练级到70，并在换图、回城、补给、掉队时按明确状态处理。

## 项目边界

- 本目录保存此项目的路线编排、恢复策略和专项实验脚本。
- 通用能力继续复用 `batch_provision/research/shitu/` 与 `batch_provision/provisioner/`：内存读取、原生寻路、地图切换、PP鸡、组队、回城、背包与商店、战斗状态、宠物施法、技能捕获封包。
- 师徒 B+、转元素使各有自己的配置与流程。本项目不复制或改写它们的任务编排；共用模块只做向后兼容的通用增强。
- 角色、技能和策略参数只在 `team.toml` 里配置（或用 `SHITU_TEAM_CONFIG` 指向另一份）；`_bootstrap.py` 在任何共享模块导入前把它写入 `SHITU_*` 环境变量，命令行已设置的环境变量优先。单独运行任何一段脚本都控制同一队角色。不要把账号密码写进来。
- `run_level_to_70.py` 是正式的 1→70 监督入口：按四个小号的最低等级从 `policy.LADDER` 选段（古井10→轮回14→暗影18→八阵图24→遗忘洞穴28→通天一33→通天二43→东部遗址48→监狱53→陷阱囚牢58→禁锢之地70），每段以真实等级到达 `until` 为准。`run_level_43_to_70.py` 保留为兼容入口，直接调用它。
- `tour_level_maps_two_battles.py` 是“假定每图两场就切图”的路线/转场演练工具，与主控共用 `route.py` 的路线数据和 `home_supply.py` 的回城补给，但不是经验验证。

## 作战约定

- 队长职业为方士时，人物循环释放天之箭 `354`（已确认等级7）；不得回退为普攻或猎人扫射 `803`。实现复用捕获的手动技能调用路径，见 [战斗知识](../../../docs/PET_MAGIC_CONTINUOUS_CASTING_AND_TIANZHIJIAN.md)。
- 队长宠物循环释放烈焰爆发 `1504`。宠物本次动作结算后若 SP 仍大于0，立即再次施法；若 SP 为0则等待蓄力。若队长需要执行复活队员，宠物应先防御消耗蓄力点。
- 四名小号的人物和宠物均不攻击。战斗辅助只允许队长和队长宠物作为 caster。
- 队长劲爆汽水为0，立即停止刷怪并回城；每次回城汇总所有格回城券，少于20补至50；队长宠物甜点少于250补至495。队长汽水低于599时，由 `hannibal_soda.py` 带队经PP鸡到荒芜之地一区汉尼拔（NPC 2508，货架格5）按每次最多99个补至1485，逐次核验到账后全队回城。价格、货架、回城流程已于2026-11-04进行三轮现场验证。
- 小号卖杂物时包含白装、配方、三种葫芦和技能石；队长也卖杂物与技能石。出售仅按明确的可出售分类，不对任务物或绑定物做猜测。

## 惊魂监狱掉队/救援规则

1. 发现缺员立刻取消队长寻路并停刷；队长单独去监狱内接人点 `(2369,2000)`，到达后原地稳定3秒。
2. 活着且仍在迷宫的小号留在当前位置，不让小号穿迷宫去找队长。队长单人走向队员，靠近后由队长发起邀请组队。
3. 死亡并回到城里的小号：其余活队员留在迷宫；队长单人回城接人。小号有飞鞋且飞鞋可用时，直接飞到龙之都内城记录点；队长随后到内城寻路靠近并邀请。
4. 小号飞鞋冷却中：不重复发飞鞋；队长等冷却。如果小号没有PP鸡权限或飞鞋不能用，走内城入口兜底；当前服铁男确认页实测标价4万金币，须逐号核对提示和余额后确认。已有飞鞋记录但飞鞋刚用过且回不来时，小号自己付费进城/监狱作为兜底。
5. 两名或更多小号死亡时逐个或分批按同一原则接回；队长不能把仍活着的迷宫队员一起带离。小号重新到内城后，队长靠近邀请；再由队长带队进入监狱并寻路到迷宫中存活队员身边重组。
6. 任何前置条件、地图位置、队伍名单或入场菜单不明确时停止并报告，不盲目连续使用飞鞋或让队员独自跑图。

代码现状说明：`prison_patrol.py` 打到53级后返回，由监督程序启动陷阱囚牢（不再在内部嵌套调用）。检测缺员后会暂停巡逻，队长先到 `(2369,2000)` 稳定等待3秒。小号若已回城会先卖指定杂物；随后队长单人回城，在小号飞鞋可用后于龙之都内城接应并组队进监狱。飞鞋冷却时等待，不重复请求；缺少有效记录时走PP鸡、交叉口与铁男路线，并且只有当前提示明确为40,000金币且角色余额足够才确认。进入监狱后，活着的迷宫队员留在原地，队长逐个寻路靠近并邀请；五人重新到齐后恢复巡逻。

## 自动恢复规则（`run_level_to_70.py`）

- **原则：可恢复的失败永不放弃。** 程序只在三种情况下退出：客户端读不到（掉线/网络）超过 `offline_wait_seconds`（默认15分钟）仍未恢复；金币或背包空间不足，必须人工处理；按 Ctrl+C。
- 其余所有失败——倒地/缺员/队伍分散、队长汽水为0、寻路卡住/误切图、菜单或商店没响应、等待超时、程序内部异常——一律：全员回城 → 卖物 → 补回城券/甜点/汽水 → 重走当前段。回城补给这一步本身失败也会退避重试。
- 没有重试次数上限。同一段连续失败（期间没有任何小号升级）时，每次重试前的等待依次为 0、30、60、120… 秒，最长 `retry_backoff_cap_seconds`（默认600秒），避免对同一个故障狂刷。
- 连续第3、6、9…次失败时**降档**：先去下一档更容易的图（跳过监狱）练1级再回来；降档图也连续失败则再降一档。只要有人升级，连续计数就清零、等待也回到0。
- 惊魂监狱：有人在监狱外或缺员时先交给监狱接人状态机；接人状态机自身失败时兜底全员回城，再从头进监狱。
- 队长汽水在每段巡逻中（脱战时）检查，为0立即停刷，交给监督回城去汉尼拔补给。
- 复活：`team.toml` 的 `revive_item`（默认美味小强料理 27002）。队长背包有该道具才启用，普通地图和监狱战斗中都会复活倒地小号（复活回合宠物防御），此时一段允许倒地 `max_falls_with_revive` 次；没有道具时首次倒地即回城重跑。
- 卖物：队长只卖杂物/残骸/技能石/图纸/配方（不碰装备）；小号另卖白装和葫芦。`sell_worn_white=false`（默认）时只卖背包里的白装，不扒身上穿着的。
- 监狱接人飞鞋冷却：剩余不超过 `shoe_wait_max_seconds`（默认600秒）就等；更久则改走铁男付费入城（40,000），小号金币不足时队长先转60,000。回监狱前全队飞鞋冷却过久时同样改走付费入城。

## 尚未实现 / 仍需现场验证

- **宠物练级目标**：内存读取层没有宠物等级（`world.Pet` 只有 MP 和技能），主控只能按小号人物等级选段，不能保证宠物到70；宠物加点、宠物死亡也未处理。需要先找到宠物等级偏移。
- 1→43 七段的路线数据来自两场演练脚本（转场已跑通），但完整按等级练级尚未实跑；全新1级号还需要先具备 PP鸡权限和买回城券的金币，否则在补给/PP鸡一步会停下报告。
- 东部遗址巡逻点 `(3300,600)` 靠近地图边缘、曾误跳 map 170；现在会按“意外切图”自动回城重跑，但巡逻点本身仍需现场换一个更安全的点。
- 掉线/客户端崩溃后没有自动重登：监督会等待 `offline_wait_seconds`，期间客户端恢复就继续，否则停止。

## 本目录文件

- `team.toml`：唯一的队伍与策略配置。
- `run_level_to_70.py`：1→70 监督主控；`run_level_43_to_70.py` 为兼容入口；`monitor_run.py` 只读监控（客户端暂时掉线时继续记录）。
- `policy.py`：纯逻辑（选段、停止分类、重试计数、地瓜识别、背包格数、飞鞋策略），由 `tests/test_fullcrit_policy.py` 覆盖。
- `route.py`：11张图的路线与巡逻点数据；`guards.py`：汽水守卫、复活开关；`home_supply.py`：回城、卖物、补给、入城费转账、PP鸡。
- `tour_level_maps_two_battles.py`：两场切图的路线演练。
- `ruin_east_43_48.py`：巨石东部遗址路线和地瓜（只吃普通/御加钙地瓜，按角色ID记录已吃，换一批同名号也会再吃）；默认目标48，可由 `SHITU_TARGET_LEVEL` 覆盖用于单段验证。
- `ruin_east_to_prison.py`、`prison_patrol.py`：东部遗址到监狱流程与监狱巡逻/队长战斗。
- `trap_cage_53_58.py`、`jingu_47_70.py`：陷阱囚牢、禁锢之地专段。
- `pet_freecast_patrol.py`：魔法宠物不扣SP连续施法机制实验。
- `pet_level_40.py`：宠物等级专用实验包装器；它与人物1→70练级主线分开运行。
- `return_by_pp.py`、`rescue_scrollless_apprentice.py 小号名`：回城/路线恢复辅助。
- `_bootstrap.py`：将共享 `shitu` 和 `batch_provision` 模块加入导入路径，确保本目录可独立启动而仍复用公用实现。

## 运行前检查

1. 确认实际在线角色、职业、队伍首位、地图权限、飞鞋记录和背包补给；本项目文档不保存账号口令。
2. 在目标机器上用当前客户端版本静态检查导入和模块版本；再用单图、小批次验证实时封包、技能响应、经验变化和补给商店货架。
3. 每次切图后核验五人均到图、队伍完整和全员等级；任何队员倒地、队长断蓝、导航卡住或门选项不匹配即停止。
4. 两场演练结果不得推断成达到等级门槛。路线完成必须由四名小号的实际等级读数逐段确认。
