# 答题器源码（2.101 版 + boss 题）

这里是 `启动答题器.exe` 和 `quizbot_hook.dll` 的源码。原来只有编译好的文件，源码在 `D:\Codes\Gemini_Prj\smsm2_game\quiz_dismiss_bot\`（2.98 地址，不在 git 里）。2026-10-27 复制进来，改成 2.100，并加上 boss 题。

## 和原来发布版的关系

- 原来包里的 2.100 版是把 2.98 编译产物里的地址数字直接改掉（提交 8c94697）。逐字节对比过：除了这些地址，和 Gemini 目录里编出来的文件完全一样，所以这份源码就是发布版的源码。
- 地址全部集中到 `dll/game_addrs.h`，以后换游戏版本只改这一个文件。
- Gemini 目录里的 DLL 源码在编译之后（10-09）又加了一个「本场最低血量」功能，从来没发布过。它要调用三个 2.98 地址（0x10070、0x100D0、0x5166DC），2.100 里对应在哪还没核实，调错会让游戏崩溃。所以用 `QB_ENABLE_MIN_HP` 开关关掉了（默认 0）。关掉以后，战斗结算事件里会多出 `min_hp` / `max_hp` 两个字段，值都是 0，控制器不用它们。

## boss 题（0x46F5）怎么做的

协议、内存、答案规律见 `batch_provision/research/shitu/BOSS_QUIZ.md`。题号 2601～3000 共 400 题全齐。

| 步骤 | 在哪 | 做什么 |
|---|---|---|
| 收题 | `dll/quizbot_hook.cpp` handle_frame | 收到 0x46F5，跳过 4 字节 char_id，按 0x46F4 的格式解析，丢掉空的第 5 项，推 `{"type":"question","kind":"map",...}` |
| 决策 | `controller/boss_quiz.h` decide | 按题号查 `data\boss_bank.tsv`，按答案文字找选项（选项换位置也能找到，文字对不上不用旧下标）；题库里没有的新题号才排除干扰项（书名号 + `data\boss_decoys.txt`），排除后剩一个就选它，否则选剩下的第一个（控制台「[猜的]」标红） |
| 作答 | `controller/main.cpp` handle_map_question → `dll` answer_map_quiz | **静默**，等 1.5 秒后走游戏自己的提交函数：面板开着、题号对得上、0x1F05 模式时写下标、调提交、再 CloseDialog。只发一次 0x1F05，和手动点完全一样。3 秒内面板没就绪就直接发 0x1F05 包 |
| 记表 | `report_map_result` → `handle_map_result` | 收到「测试通过！」后报出题号和下标，控制器把这一行的来源改成「实测」。只有面板确实显示过这道题、现在已关，才算用户手动答的；否则这条「测试通过」属于别的题（见上线记录 10-30） |

题库文件由 `tools/gen_boss_bank.py` 从 `data/boss_questions_0x46f5_20261030.json`（400 题采集数据）生成：
`boss_bank.tsv` 第 5 列来源 = 实测（游戏里答对过）/ 推算（按规律 **正确下标 = (题号 − 2601) ÷ 100**）；
`boss_decoys.txt` = 400 题的全部错误选项（只读，不再在线学）。题目有变化时更新 JSON 再跑脚本，和实测冲突会报错不写文件。

师徒脚本的兜底 `batch_provision/research/shitu/boss_quiz.py` 用同一份题库、同一套规则。

## 辅助工具界面解锁（2026-10-28 合进来）

`controller/native_unlock.h`，`main.cpp` 的主循环调用：每个已注入的游戏窗口打两个内存补丁（不改 exe 文件），
游戏自带「辅助工具」的 **战斗辅助页**、**自动采集页** 不再置灰、不再显示「（待激活）」。启动参数 `--no-unlock` 关掉。

- 来源：`D:\Codes\Gemini_Prj\smsm2_game\战斗辅助原生界面解锁工具\`（2.97 版，Gemini 写的 C / Python 小工具）。
  按项目规矩只拿事实——两段特征码和补丁字节；代码重写，接进答题器的进程守护，不用另开一个程序。
- 地址：`dll/game_addrs.h` 的 `RVA_UNLOCK_FIGHT = 0x5F570`、`RVA_UNLOCK_GATHER = 0x5F2BF`（2.97 是 0x5EA20 / 0x5E76F）。
  先查这两个地址；对不上就扫描整个模块找特征码（游戏小更新也能找到）；特征码出现两次以上就不打。已经是补丁后的字节 = 已解锁。
- 补丁含义（详细注释在头文件里）：界面每帧检查身上有没有辅助卡，没有就整页 SetEnable(0)；补丁让「有没有」的结果恒为有。
  采集页补丁的跳转目标和原版一样（+13），测试里核对。
- 一个窗口没解锁成功（刚启动、模块还没映射全）会每 1.5 秒再试，最多 10 次。控制台「[解锁]」一行一个窗口。
- 离线测试 `tools/native_unlock_test.cpp`：人造缓冲区（原版 / 已补丁 / 没有 / 出现两次）+ 读 `local.toml` 里的 2.100
  WAATClient.exe，按 PE 节表算出两段特征码的 RVA，必须各只出现一次、正好等于 game_addrs.h 的值。
- 还没在游戏里打开辅助工具看过效果（上线后看一眼两页是不是都能点）。
