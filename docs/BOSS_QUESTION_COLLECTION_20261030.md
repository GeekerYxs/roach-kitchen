# Boss 开打题：400 个题号的采集记录

记录日期：2026-10-30。数据文件：[`boss_questions_0x46f5_20261030.json`](../%E5%A4%A7%E5%86%92%E9%99%A92_%E8%87%AA%E5%8A%A8%E7%AD%94%E9%A2%98%E5%99%A8_%E5%8E%9F%E7%94%9F%E6%97%A0%E6%84%9F%E5%85%B3%E7%AA%97%E7%89%88/data/boss_questions_0x46f5_20261030.json)。这是点 Boss「开打」后出现的地图答题（服务端消息 `0x46f5`，面板 `QuestionOnMap`），不是战斗挂机题 `0x46f4`。早期协议证据见 [BOSS_QUIZ.md](../batch_provision/research/shitu/BOSS_QUIZ.md)。

## 结果与边界

- 合并 3,838 次题目观察，收集到 **400 个不同题号，覆盖 2601～3000**，共 399 个不同题干；没有观察到区间外题号。
- 每个题号在本次记录中的题干及带序号的选项只有一种版本。相同题干可以对应不同题号和选项，例如 2776 和 2866 都问最大的半岛，但选项位置不同。应按题号匹配，并复核题干和选项；不要只按题干硬编码下标。
- 收集过程只读取题目和选项，**没有对这 400 道题逐题作答或验证服务器认可的答案**。本文件不是答案键；不要把“看起来正确”的选项当作已验证答案，也不要覆盖现有 `data/boss_bank.tsv`。题目或官方认可的答案可能随时间变化。
- 见齐这 400 个连续编号是有限题库的强证据，不能证明服务端没有其他编号、其他 Boss 的题、低频题或日后新增题。

## 已并入答题器（推算答案）

2026-10-30 按题号推出了全部 400 题的答案，写在单独的 `data/boss_bank_seed.tsv`（`src/tools/gen_boss_seed.py` 生成），**没有改 `boss_bank.tsv`**。
规律：正确下标 = (题号 − 2601) ÷ 100 取整。证据：`boss_bank.tsv` 里服务器认可过的 37 道全部符合；400 题在这个位置上都是唯一一个和题目沾边的选项。
答题器查找顺序：实测 `boss_bank.tsv` > 推算种子（只按答案文字匹配，题目改过就不用）> 排除干扰项。推算的题答对后会照常记进 `boss_bank.tsv`。
注意：有几道的「正确」选项按常识并不对（如 2743「鸡蛋煮熟是物理变化」），但它是 4 个选项里唯一非干扰项，以服务器为准。

## 数据格式

JSON 是数组，每条包含 `qno`（题号）、`observations`（本次合并记录的观察次数）、`variants`（观察到的题干和完整选项列表）。`variants` 是数组，保留它以便未来发现题目或选项变化时记录多个版本；本次每个题号恰有一个版本。`options` 的文字保留游戏显示的 `1、` 至 `4、` 前缀；协议答案使用从 0 开始的下标，但本数据没有答案字段。

仓库中 LF 换行版本的 SHA-256：`e29bc214a12b80333413ba726a4cc93312c80b190982ba71903f8609b96342fc`；Windows 工作区若转换为 CRLF，文件哈希会不同。文件只包含题号、观察次数、题干和选项，不包含账号、密码、PID 或进程内存地址。

## 如何采集

1. 在逍遥村西区向鹰眼林长治接「不死的拉灯之魂」（任务 49），到阴森古井（地图 651）拉灯附近。NPC 交互 ID 为 1118。通过现有 `provisioner.game.Game` 的客户端原生调用对话拉灯，选择菜单「开打」，没有使用物理键鼠或逐帧截图。
2. 弹出 Boss 题时，调用 [`boss_quiz.read_panel`](../batch_provision/research/shitu/boss_quiz.py) 只读题号、题干、选项和可见状态；不调用 `solve`，不提交答案。随后保存数据，再关闭本次启动的客户端。
3. 使用一键登录器的 `login_engine.exe` 后端和 `provision_native.dll`，每个账号同一时刻最多一个本次采集进程。各账号并发启动，标准输入传凭据；登录成功后等内存中 Boss 题面板可读，读取后关闭该进程，立刻启动该账号的下一次。登录报告、题目事件和出错阶段分别记录；登录或读取状态异常的账号单独停止，其他账号继续。本次实际观察到重登后会出现新题；这不证明所有角色、场景和版本都如此。
4. 环境为 Windows，游戏客户端 2.101，`WaatClient.exe` SHA-256 `ce609262b998d345bedc73b7529c89034f27db9380787278e3fd4226f9fa6100`。`QuestionOnMap` 和字段偏移以仓库当前 `provisioner/world.py` 与 `research/shitu/boss_quiz.py` 为准；更新客户端后应重新核验。此次批量题目来自内存面板；`0x46f5` 的网络格式是已有历史封包研究，不应误称每个新样本都有独立网络抓包。

采集器采用 30 个并发上限、全局启动间隔至少 0.3 秒。同一账号一个进程，获取后关闭；不将账号密码、进程日志或本地配置提交到 Git。最后一个缺号 2746 在额外采集的第 327 次出现，停止启动后还保存了正在处理的样本。本次收集的末题为「世界上人口最多的国家是什么？」，原始选项照录，不代表已验证答案。

## 吞吐实验

六组各开放 90 秒启动新请求，随后等待已启动的请求保存并关闭；“题/分钟”按包含收尾的实际耗时计算。账号集因错误隔离并不完全相同，每组只测一次，不能当作严格基准。

以含收尾吞吐量计，这次 30 / 0.3 最快；该组最低可用物理内存约 3.49 GiB。前 90 秒的最高值则是 8 / 0.3 的 88 题。没有同时采集网络延迟和 CPU 峰值，不能据此判断瓶颈是网络、内存还是其他资源。每组独立题干数分别为 84、85、95、101、96、85；各组可能互相重复，不能相加作为总题库数。
