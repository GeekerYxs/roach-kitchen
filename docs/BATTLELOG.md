# 战斗记录（battlelog）：每一场战斗都记下来，事后随便分析

这份文档写给**用工具的人**：它能记什么、怎么开、怎么看报表、目前从数据里得出了哪些结论、遇到问题怎么办。
写给 agent / 改代码的人的技术细节（包格式、偏移、证据、数据库表、怎么扩展）在
[batch_provision/battlelog/README.md](../batch_provision/battlelog/README.md)。

---

## 0. 一页看懂

- **它是什么**：把游戏里的每一场战斗变成数据库里的一行。记的内容包括在哪打、打了多久、巡逻多久、遇到哪些怪（名字和等级）、
  队友是谁、拿了多少经验 / 潜能 / 宠物经验 / 训练经验、掉了什么、谁阵亡了、有没有逃跑、开着哪些双倍、金币和背包怎么变、
  有没有被答题打断。
- **数据从哪来**（两个来源，互相补充）：
  1. **监听文件**（`runtime/tap_<pid>.jsonl`）：我们的 DLL 在游戏里"旁听"服务器发来的包，只看不发。
     用我们登录器开的窗口自动就有，别的窗口可以用 `research/shitu/attach_tap.py` 挂上去。
     **战斗本身的信息**（怪、奖励、掉落、阵亡、双倍）都从这里来。
  2. **读内存**：和经验监测一样，只读不写，不需要 DLL。**金币、背包、答题弹窗、自己的等级**从这里来。
- **存在哪**：`batch_provision/logs/battlelog/battles.sqlite`（SQLite 数据库，一个文件；`logs/` 不上传 GitHub，
  每台电脑各自一份）。分析报表写到同目录的 `report.md`。
- **现在的规模**（2026-10-29）：1171 个监听文件导入了 **64309 场**（10-26 晚到 10-29 上午，92 个角色），
  其中 64293 场有结算；数据库约 290 MB。
- **三个按钮 / 命令**：

| 想做什么 | 怎么做 |
|---|---|
| 把电脑上已有的监听文件导进数据库（随时可以重复点，没变化的文件会跳过） | 双击 `batch_provision/一键导入战斗记录.cmd` |
| 一边挂机一边实时记（加上金币、背包、答题） | 改 `batch_provision/battlelog.toml` 里的角色名 → 双击 `batch_provision/一键战斗记录.cmd` |
| 出分析报表 | 在 `batch_provision` 目录里运行 `python -X utf8 -m battlelog report`，看 `logs/battlelog/report.md` |

> **安全**：两个来源都是只读的。导入只读文件；实时记录只读游戏内存（ReadProcessMemory），不注入、不发包、不点界面，
> 不会影响挂机。监听用的 DLL 是早就在用的那个（登录器 / 师徒线），这个工具没有新的 DLL。

## 1. 每场记了什么

一场 = 从遇敌（服务器发"开战"包）到自己的结算包。下面按"能从哪里拿到"分组。
"历史"这一列表示：只有监听文件、没开实时记录时，这一项有没有。

### 1.1 时间和地点

| 内容 | 说明 | 历史 |
|---|---|---|
| 开战时间、结束时间 | 真实时间（精确到约 0.1 秒）。离线导入时用文件修改时间换算，和内存记录的偏差在 2 秒内 | ✅ |
| 战斗用时 | 开战到结算 | ✅ |
| 巡逻用时 | 上一场结算到这一场开战（走路找怪的时间）。一个文件的第一场没有 | ✅ |
| 地图、遇敌坐标 | 服务器开战包给的 | ✅ |

### 1.2 人

| 内容 | 说明 | 历史 |
|---|---|---|
| 自己的角色名、等级 | 开战包**不列自己**，只列队友；所以从**同一时刻队友的记录**里取（队友的包里有你）。单人打怪、或队友没开监听时为空，实时记录时从内存补上 | ✅（99%） |
| 自己 / 自己宠物的站位 | 开战包头里 | ✅ |
| 队友：名字、等级、站位、血量 | 开战包 | ✅ |
| 队友宠物的等级 | 开战包 | ✅ |
| 战斗中升级 | 战斗里收到的升级包 | ✅ |

### 1.3 怪

| 内容 | 说明 | 历史 |
|---|---|---|
| 每只怪的编号、名字、等级、站位、血量上限 | 开战包；名字来自游戏自己的怪物表（7062 个怪） | ✅ |
| 打死了几只 | 战斗中的"出局"包 | ✅ |

### 1.4 收获

| 内容 | 说明 | 历史 |
|---|---|---|
| 人物经验、宠物经验、宠物训练经验、潜能 | 服务器结算包给的**精确值**。人物经验已和内存读数逐场核对：1706 场里 1697 场完全一致 | ✅ |
| 掉落：物品、数量、进了背包哪一格 | 结算包；物品编号全部能在物品表里找到 | ✅ |
| 金币变化 | **战斗不掉金币**，所以这里是"上一场结束到这一场结束"之间的变化（卖东西、交任务等） | 只在实时记录时 |
| 背包变化 | 同一段时间里每种物品多了 / 少了几个（掉落、吃药、卖掉） | 只在实时记录时 |

### 1.5 战斗过程

| 内容 | 说明 | 历史 |
|---|---|---|
| 本人阵亡、宠物阵亡、队友阵亡几个 | 战斗中的"出局"包 | ✅ |
| 逃跑：试了几次、成没成功 | 我方发出的逃跑指令；"成功" = 试过逃跑而且怪没打完 | ✅ |
| 我方指令次数 | 人物：普攻 / 技能 / 法术 / 逃跑 / 用道具；宠物：普攻 / 法术 / 防御 | ✅ |
| 对目标用道具（吃药）：用了背包哪一格 | 我方发出的用道具指令 | ✅ |
| 答题弹窗：几次、一共多少秒 | 读内存；算在"上一场结束到这一场结束"之间 | 只在实时记录时 |
| 每回合最低血量 | **还没做**，见第 5 节 | ❌ |

### 1.6 双倍和加成

| 内容 | 说明 | 历史 |
|---|---|---|
| 人物经验倍数、潜能倍数、宠物经验倍数、宠物训练倍数 | 服务器的状态包：开战那一刻开着哪些，倍数多少 | ✅ |
| 每个状态还剩多少秒 | 同上（例如散福的 3 小时 = 10800 秒，每领一次加 3600） | ✅ |
| +20% 人物经验 | 同上（状态 1019） | ✅ |

四种双倍对应四种道具（物品表）：30067 人物经验、30070 宠物经验、30071 宠物训练经验、30204 潜能；
（御）黄金搭档是四项合一。散福老人给的是人物经验双倍。

### 1.7 原始数据（以后再解）

每场的开战包、结算包**原样保存**，战斗中双方的所有包压缩后也存着。以后解出新字段，可以从数据库直接重算全部历史，
不用重新挂机，也不用重读监听文件（`python -X utf8 -m battlelog rebuild`，6.4 万场约 12 秒）。

## 2. 怎么用

### 2.1 导入已有的监听文件

双击 `batch_provision/一键导入战斗记录.cmd`，或者在 `batch_provision` 目录里：

```bash
python -X utf8 -m battlelog import
```

- 默认扫描 `runtime/`（登录器开的窗口）和 `research/shitu/runtime/`（师徒线挂的监听）。也可以在后面写别的文件夹。
- **可以随时重复运行**：大小和修改时间都没变的文件直接跳过；还在写的文件会重新读一遍，旧行被替换。
- 第一次导入 1.3 GB / 1171 个文件约 1 分半；之后只处理变了的文件。
- 加 `--force` 会忽略"没变化就跳过"，全部重读（解码规则改了、需要从监听文件重新取状态包时用）。
- 导入完会自动：从队友记录补自己的名字和等级、合并实时记录的内存数据、在屏幕上打印各地图汇总。

### 2.2 实时记录

1. 打开 `batch_provision/battlelog.toml`，在 `roles` 里写要看的角色名（和窗口标题里 `-cap01_` 这一段一致）。
2. 双击 `batch_provision/一键战斗记录.cmd`，开着就行，关掉窗口就停。

它会：
- 每 0.3 秒读一次每个窗口的内存（在不在战斗、地图、坐标、等级、经验、金币、背包、答题弹窗）；
- 每场战斗结束时在屏幕和日志里打一行，例如：
  `cap01 45级 地图281 经验+1725 金币+0 物品{8454: -2} 答题0次0s 巡逻5.1s`；
- 每 10 分钟导入一次监听文件，并把内存这一半合并到对应的战斗行里（按窗口 + 开战时间对齐）。

窗口关了会自动重新找；没开 DLL 的窗口也能记（只有内存这一半）。日志在 `logs/battlelog_*.log`。

### 2.3 分析报表

```bash
python -X utf8 -m battlelog report
```

屏幕上打印，同时写到 `logs/battlelog/report.md`。六个部分见第 3 节。

### 2.4 其他命令

| 命令 | 作用 |
|---|---|
| `python -X utf8 -m battlelog summary` | 各地图一行的快速汇总（场数、等级范围、平均经验、战斗 / 巡逻秒数） |
| `python -X utf8 -m battlelog rebuild` | 用库里已存的原始包重算"战斗过程"那些列（阵亡、逃跑、指令） |
| `python -X utf8 -m battlelog import --force` | 全部监听文件重读一遍（重算双倍状态需要这个） |

想自己查数据：数据库是普通 SQLite，可以用 DB Browser for SQLite 打开 `battles.sqlite`，表 `battles` 一行一场，
表 `npcs` 是怪物名字，表 `mem_battles` 是实时记录的内存数据。列的含义见 agent 文档第 4 节。

## 3. 报表怎么读，现在的结论

报表把经验一律换算成**单倍**（开了人物双倍的场次除以 2），这样开双倍和不开的场次能放在一起比；
"每小时" = 战斗 + 巡逻时间（巡逻超过 120 秒算暂停，不计）。每格至少 30 场才列出来。

### 3.1 每个等级哪张图最快

下面是 2026-10-29 的结果（单倍万经验/小时，主要是师徒线大带小的数据）：

| 等级 | 最快 | 万/时 | 怪物等级 |
|---|---|---|---|
| 3–10 | 阴森古井 | 4.6–9.2 | 8–10 |
| 11–14 | 轮回之城 | 11.0–11.9 | 12–13 |
| 15–18 | 暗影迷城 | 13.0–14.6 | 16–17 |
| 19–24 | 八阵图 | 17.0–21.1 | 21–22 |
| 25–26 | 遗忘洞穴 | 24.9–27.2 | 26–30 |
| 27–34 | 通天塔一区 | 31.3–58.2 | 33–35 |
| 35–40 | 通天塔二区 | 52.2–59.4 | 38–40 |

也就是说，路线 **古井 → 轮回之城 → 暗影迷城 → 八阵图 → 遗忘洞穴 → 通天塔一区 → 通天塔二区** 每一段都已经是数据里最快的，
换图点：**15 级进暗影迷城、19 级进八阵图、25 级进遗忘洞穴、27 级进通天塔一区、35 级进通天塔二区**。

### 3.2 等级差曲线（最重要的一张表）

先在每张图里算"这场单倍经验 ÷ 这张图能拿到的满额"，再取各图的中位数：

| 人物等级 − 怪物平均等级 | −8 | −7 | −6 | −5 | −4 | −3 ~ +3 | +4 | +5 | +6 | +7 | +8 | +9 | +10 及以上 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 相对满额 | 37% | 51% | 68% | 87% | 86% | 94–99% | 85% | 76% | 65% | 49% | 34% | 17% | ≈0 |

- **最佳区间：比怪低 3 级到比怪高 3 级。**
- 比怪低 5 级还能拿 87%，低 6 级掉到 2/3，低 8 级只剩 1/3。
- 比怪高 4 级开始掉，高 7 级只剩一半，**高 10 级以上基本没有经验**。
  （早先口头估计"高出十几级才断崖"是错的，以这张表为准。）

### 3.3 双倍

同一张图、同一个等级里比"开人物双倍"和"不开"：**人物经验 1.99 倍，宠物经验 1.02 倍，潜能 1.00 倍**（14 个格子）。
所以散福 / 加钙地瓜只翻倍人物经验；想要宠物或潜能也翻倍，得用对应的道具或黄金搭档。
（这也是为什么开着散福时，宠物经验正好是人物经验的一半。）

### 3.4 阵亡、逃跑、答题

每张图一行：场数、本人阵亡、宠物阵亡、逃跑成功、答题次数和耗时、平均战斗秒数。
全部历史里：本人阵亡 13 次（通天塔一区 8、二区 3）、宠物阵亡 197 次（大多在通天塔二区）、
逃跑成功 198 场（通天塔一区 85、苦无沙漠1区 64、巨石之城西部遗址 21、逍遥古迹 20…）。
注意报表这一节只算"有结算而且知道自己等级"的场次，逃跑的多是单人场（不知道等级），所以报表里的逃跑数会比 198 少。
答题这一列只有开着实时记录时才有数。

### 3.5 掉落和 3.6 各图的怪

每张图掉得最多的 8 种物品（每 100 场掉几个），以及每张图最常见的 6 种怪和等级。
例如八阵图 = 猛男鼹鼠 21 级、回魂丧者 22 级、黄花闺女 21 级；通天塔二区 = 夜叉总管 40 级、柔弱的仙女MM 39 级、老不休 40 级…

### 3.7 45–60 级标准刷图点：满怪单场基准经验与升级推算公式

#### 核心底层规律（跨队伍通用）

1. **单场标准经验恒定**：同一张地图、相同怪物数量与等级、且人物 / 宠物处于 **`-3 ~ +3` 满额等级差区间**时，**单场获得的经验值是服务器固定标准值**，与队长配置、技能伤害、打几回合完全无关。
2. **队伍差异只体现在周期时长 $T_{\text{cycle}}$**：不同队伍配置（伤害高低、一回合还是两回合、巡逻快慢）只影响 **平均几秒完成一场战斗（$T_{\text{cycle}} = T_{\text{战斗}} + T_{\text{巡逻}}$）**。
3. **单倍人物经验 = 单倍宠物经验（1 : 1）**：同等级差下，单倍人物基础经验与宠物基础经验完全相等；而在经验表 `ResLib/expLib.csv` 中，**45–60 级每一级的人物升级所需经验（`playerexp`）恰好是宠物升级所需经验（`petexp`）的 3 倍**。
4. **3–5 分钟快速推算公式**：
   任意队伍只需在目标地图挂机监测 **3–5 分钟（约 12–15 场）** 测出本队平均周期 $T_{\text{cycle}}$（秒/场），即可直接算出升级耗时：
   $$\text{每小时单倍经验} = \frac{3600}{T_{\text{cycle}}} \times E_{\text{单场期望}} \quad,\quad \text{升级耗时 (小时)} = \frac{\text{目标段总经验}}{\text{每小时单倍经验} \times \text{双倍倍率}}$$

## 4. 常见问题

**Q：数据库太大了怎么办？**
290 MB 里大部分是战斗中的原始包（为了以后能重算）。可以直接删掉 `logs/battlelog/battles.sqlite` 再导入一次，
只要监听文件还在就能完全恢复；监听文件删了，数据库就是唯一的记录，别删。

**Q：为什么有的场次没有角色名 / 等级？**
开战包里不列自己。单人打怪、或者同队其他人没开监听时，自己的等级只能靠实时记录从内存补。

**Q：导入时提示"读不了"？**
多半是文件还在被游戏写、或者缺 `tap_<pid>_codec.json`（解码表）。缺解码表的文件会被跳过，不影响别的。

**Q：游戏更新了怎么办？**
战斗包的格式一般不会跟着变。要检查的只有实时记录用的内存地址：在 `batch_provision` 里跑
`python -m provisioner.addrscan`，它会自动找新地址（包括怪物等级的 `BATTLE_GRADES`）并告诉你哪里要改。
详见 [GAME_UPDATE_2101.md](GAME_UPDATE_2101.md)。

**Q：报表里某个等级没有我想看的图？**
那张图在那个等级的场次不到 30 场。多刷一会儿、再导入、再出报表。

**Q：会不会影响正在挂机的号？**
不会。导入只读文件；实时记录只读内存，不注入、不发包。

## 5. 还没做 / 已知限制

- **每回合最低血量**：游戏内存里战斗中的血量是加密存放的，读不到明文；回合结算包 `0x4109` 只解出一部分
  （动作和"效果码 + 数值"，效果码 405 看起来是伤害）；而且开战包不列自己，单人打怪时不知道自己开战时的血量。
  下一步方案：反汇编游戏的 `GetHp()`，看它怎么解密，再在 Python 里只读地算出来。
- **结算包尾部几个数**：随战斗变化（学徒每场几百，师傅固定 1744 / 748），含义未知（不是金币，战斗不掉金币）。原样保存着。
- **结算面板对照**（2026-10-29 截图：欧皇丨花花乀 70 级 + 魔力布老虎 44 级，在通天塔二区）。
  面板显示：人物经验 1、潜能 0、宠物经验 3014、训练经验 3。
  - 和数据库里的规律都对得上：
    - 70 级打 38~40 级怪，人物经验只有 1~2，不会是 0。
    - 人物经验只有 1~2 时，潜能一定是 0。
    - 宠物经验按宠物自己的等级算，和主人无关：44 级宠物照样拿 3014。
    - 训练经验只有固定几档（0/3/7/10/14/20），和宠物经验多少无关。
  - 那个窗口没挂 DLL，所以没能和这一场的包逐字节对上。以后在挂了 DLL 的窗口截一张就能彻底确认。
- **金币、背包、答题**只有实时记录时才有，历史数据里补不回来。
- 监听文件只有挂了 DLL 的窗口才有；没挂 DLL 的窗口只有内存这一半。
