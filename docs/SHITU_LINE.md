## 0. 一页看懂

- **一键**（在 `batch_provision/research/shitu/` 下）：`python -X utf8 -m line`。停：建空文件 `logs/LINE_STOP`（当前批跑完再停）。
- **队**：`line/line.toml` 里每个 `[team.<队名>]` 一队 = 1 个 70 级师傅 + 每批 4 个新建徒弟。`teams = [...]` 选这次跑哪几队，
  `batches = [...]` 跑第几批（第 N 批用每个徒弟账号的第 N 个角色位）。
- **两种转职**：默认勇者（B+ 路线）；`job = "术士"` 的队走元素使（`route.ROUTE_YUANSU`，见 `research/shitu/YUANSU_NOTES.md`）。
- **一批的产出**：每个徒弟 41 级、勇者、约 48 万金币，最后全部交易给师傅（`give_gold.py`）。
  元素使线不同（2026-11-05 用户）：金币留在徒弟身上不交给师傅（元素使以后练到 70 当队长）；最后打开背包里的囧盒仔，让囧盒仔出战（`jiong.py`）。通天二出塔点 40 级 + 70,000，出师后 41 级。
- **一批用时**（2026-10-31 夜六队实测）：满爆小法 2:35–2:50，伏地魔 3:10–3:25；之后几次优化（见第 5 节）还没整批实测。
- **前提**：师傅按 [SHITU_MASTER_GUIDE.md](SHITU_MASTER_GUIDE.md) 准备好；`启动答题器.exe` 不用手动开：总控每批开始前检查，没开就自动启动，启动失败才报警。

## 2. 结构

```

   └─ line/runner.py   跑一队一批：逐步执行路线；健康检查、卡死检测、重试阶梯、排除、断点

各步调用 research/shitu/ 下的脚本（按文件名），共用能力见 ARCHITECTURE.md 第 3 节。
```

## 3. 用法（在 `batch_provision/research/shitu/` 下）

| 做什么 | 命令 |
|---|---|
| 全部队一批接一批 | `python -X utf8 -m line` |
| 只跑几队 | `python -X utf8 -m line --teams a,c` |
| 看进度 | `python -X utf8 -m line --status` |
| 只看要执行的命令（不碰游戏） | `python -X utf8 -m line --dry-run --teams d` |
| 一队一批补跑几步 | `python -X utf8 -m line --team a --batch 3 --from king --until king` |
| 只带几个徒弟补跑 | 再加 `--apps 亿万35,亿万36` |
| 停 | 建空文件 `logs/LINE_STOP` |

日志：`logs/<LOGID>_line_<段>.log`（每步一行 `== STEP 名 时间 apps=…`，每条命令一行 `$ …`）；
进度 `logs/<LOGID>_line.json`；全局 `logs/line_state.json`；报警 `logs/line_alert.log`。

### `line/line.toml` 每队能写什么

| 字段 | 意思 | 默认 |
|---|---|---|
| `master` | 师傅角色名 | 必填 |
| `slot` | 第几组账号和徒弟名（0–3：账号 cap(21+4·slot)…+3，第 N 批徒弟 亿万(16(N−1)+4·slot+1)…+4） | 0 |
| `accounts` / `names` | 不用 slot 时自己指定：第一个账号号码、角色名前缀 | — |
| `pool` | 给一个账号范围，如 `"mw01-mw100"`（要和 `names` 一起写）。每批开始前总控按顺序挑 4 个还有空槽、而且不在任何一队最近一批里的账号；挑中的 4 个会先登录到选角色界面核对一遍，满了就换下一个。挑的结果记在 `logs/pool_alloc.json`，重启后沿用；读到的角色列表缓存在 `logs/pool_rosters.json`（`line/pool.py`，2026-11-05 用户：只给账号范围，空槽自己找） | — |
| `gold` | 师傅给每个徒弟的启动金 | 10000 |
| `route` | 只能是 `bplus`（写 `v5` 会报错；不写就行） | bplus |
| `job` | `战士`（勇者）/ `术士`（元素使） | 战士 |
| `tower1` | 通天一练到几级 | 35 |
| `tower2` | 通天二出塔点：`auto`、`40` 或 `39+150000` | auto |
| `levels` | 各图离开等级，如 `{ lunhui = 12, cave = 28 }`（洞穴不能低于 28） | 见 plan.py |
| `skip` | 某批不带谁：`skip = { "2" = ["亿万J8"] }`（写原名也行，会按改名记录对上） | — |

队名同时是 LOGID（`r4<队名>_b<批>`）和 `line_state.json` 的键：换师傅就起个新队名。同一组账号或同一个师傅不能同时在两队，启动时会检查。
全局设置：`retries` 3、`recover_tries` 2、`recover_wait` 120、`silent` 900、`stagger` 60、`park_retries` 3、`park_wait` 600、
`master_accounts`（师傅账号文件，用户本机，不进仓库）。

## 4. 出问题时它自己怎么办

1. **每步开始前查窗口**：师傅窗口没了或掉线 → 用 `master_accounts` 自动重登，全员回城，重跑这一步（每步最多 3 次）；
   徒弟掉线 → 关窗重登（`r4_util windows`）。
2. **步骤中途掉线**：练级 / 走路循环里某人 30 秒读不到状态就报「掉线？」让这一步失败（`trial_run.Gone`），重跑前会重登。
   答题弹窗 90 秒没人答也报错（「启动答题器 没开？」），不再空等到 15 分钟。
3. **卡死**：日志 900 秒没变化 → 杀掉这一步，算一次失败。
4. **失败阶梯**：第 1–3 次 = 清场 + 5 秒再跑。清场按每步的 `retry`：`home` 全员回城；`leave` 原地离队，
   **但大家散在不同地图时改成全员回城**（每一步从逍遥村重来都能走通，有测试）。回城、离队前先关掉每人开着的对话框。第 4–5 次 = 徒弟全部关窗重登 + 回城 + 等 120 秒。
   还不行：后段任务闸门没过的徒弟被排除（留在师傅名下，以后每批少建一个），其余人继续；否则这一队停摆报警。
5. **停摆后自动再试**：等 600 秒从断点接着跑，最多 3 次。
6. **跳过的批次**：某批的名字全在 `skip` 里 → 直接记完成、下一批。前面跳过了一批，后面建角照样能建（第 N 批的槽是上限，不是精确值）。

## 6. 人什么时候要管

| 报警 / 现象 | 要做的 |
|---|---|
| `MASTER_DOWN` / 自动重登师傅都失败 | 手动登录那个师傅，站在逍遥村，重启总控（会从断点接着跑） |
| 一队停摆，自动再试 3 次都不行 | 看 `logs/<LOGID>_line_<段>.log` 最后的「停止:」，对症处理后 `--team <队> --batch <批>` 续跑 |
| 徒弟被排除（占师傅名额） | 决定去留：留着以后重做任务，或解除师徒（协议见 `ANALYSIS.md`，还没自动化） |
| 账号角色位用完 | 加账号或删旧角色（`delete_apprentices.py`） |
| 日志「丢不掉: [特赦令]」 | 特赦令标着重要，可能丢不掉，告诉开发 |
| 日志「没有回城卷 … 师傅接不到」 | 人工给那个徒弟回城卷，或把它带回城 |
| 日志「答题弹窗 90 秒没人答」或「自动启动也没成」 | 手动双击 `启动答题器.exe`（要管理员权限） |
| 补给 / 借回城卷 / 交金币时交易一直失败 | 看两个号是不是还开着交易窗口，手动取消（取消交易的封包还没录到，脚本关不了） |
| 游戏更新 / 地址变了 | 按 [GAME_UPDATE.md](GAME_UPDATE.md) 做（`addrscan`、地址档案、封包实测） |

## 7. 加 / 改一步

在 `line/route.py` 里加一个 `Step(名, 段, (命令...), retry=..., unless=..., env=...)`，然后在 `batch_provision/` 下跑
`tests.test_line`、`tests.test_job_route`、`tests.test_restart_from_home`（Linux 上的跑法见 `AGENTS.md`）。测试会检查：
脚本文件存在、ops 和条件名存在、没从 `logs/` 运行、回城前不组队、后段任务步有闸门、拿任务物品前腾背包、
**每一步从逍遥村重来能走通**、勇者线指纹（有意改勇者路线时同步更新）。新的游戏小操作写成 `line/ops.py` 里的函数，
能给别的线用的写进共用模块（ARCHITECTURE.md 第 5 节）。

## 8. 答题器

战斗题（0x46F4）和 boss 开打题（0x46F5）由 `启动答题器.exe` 静默答；它自动发现并注入每个新开的游戏窗口（徒弟重登后不用管）。
一台电脑只开一个，所有产线共用；每条产线启动时用 `provisioner.quizbot.ensure` 检查，没开才启动（**不能开第二个**：每次启动都会先关掉已有的答题器）。
产线 `boss_quiz.py` 兜底；boss 题答错被踢下线时，产线自动关窗重登、整步重跑。答题器还会解锁游戏自带辅助工具的战斗辅助页和自动采集页
和自动任务页（`--no-unlock` 关掉），见 `大冒险2_自动答题器_原生无感关窗版/src/README.md`。
