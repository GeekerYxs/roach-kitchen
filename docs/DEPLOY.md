# 新生产机部署指南（美味小强料理生产线）

写给第一次部署的人：照着从上往下做，每一步都有"做完应该看到什么"。不需要懂编程。
举例的机器：**16 核 32 GB 的云电脑，跑 3 个古井队长 + 6 个海岸队长**（2026-10 的生产配置，实测约 92–105 个料理/小时）。

---

## 1. 先弄明白：一条线由什么组成

| 组成 | 数量 | 是什么 |
|---|---|---|
| **工位大号** | 11 个账号 | 常驻在线、干固定活的角色：1 调度员 + 3 古井队长 + 6 海岸队长 + 1 收货人 |
| **小号** | 一个号段，约 130 个账号 | 程序自动建角 → 练到 11 级 → 刷材料 → 交出料理 → 删除 → 3 小时后重建，一直循环 |
| **这台电脑** | 1 台 | 跑"总大脑"（`一键总大脑.cmd`），它指挥所有窗口 |

小号的一生（全自动，你不用管）：
新手出村 → 吃小肉林、记飞鞋 → 调度员给 500 金币 → **古井队长**带到 11 级 → **调度员**坐 PP鸡 送到海岸 → 接任务 78 →
**海岸队长**带着刷腿和鸡屁股 → 交任务拿到料理 → 去花袭人脱下扳手、把能卖的全卖掉 → 把料理和全部金币交给**收货人** → 删除。

工位大号自己也会照顾自己：回城卷、药、宠物甜点低了自己去买，背包快满自己卖杂物，金币不够自己去收货人（财政主管）那里领。

---

## 2. 硬件和系统（以 16 核 32 GB 为例）

| 项目 | 建议 | 为什么 |
|---|---|---|
| 内存 | 32 GB 能开约 35–40 个游戏窗口（11 工位 + 约 25–30 小号） | 实测内存是上限：空闲内存低于 1500 MB 时程序会暂停开新窗口 |
| 页面文件（虚拟内存） | **固定 32 GB**（系统 → 高级系统设置 → 性能 → 高级 → 虚拟内存） | 每个游戏窗口约占 720 MB"提交大小"，不设大的话第 30 个窗口左右就开不出来 |
| CPU | 16 核够用 | 小号窗口最小化后每个约省一半 CPU |
| 磁盘 | 游戏 2.4 GB + 日志，留 20 GB | |
| 电源 | "从不睡眠"，关闭 Windows 更新自动重启 | 睡眠 = 全线停 |
| 杀毒 | 把游戏目录和代码目录加进 Windows 安全中心的排除项 | 启动器会往游戏里注入 DLL，可能被误报删掉 |

窗口多时一定要打开**自动最小化**（见第 6 步 `local.toml` 里的 `[batch] minimize = true`），实测每个窗口实际内存从约 700 MB 降到约 300 MB，不影响任何工序。

---

## 3. 准备 11 个工位大号（最重要的一步）

每个工位 = 一个账号的一个角色。**一个账号同一时间只能有一个角色在线**，所以 11 个工位要 11 个不同的账号。
这些号**不能**和小号号段重叠，也不能同时在别的电脑上登录（会互相挤下线）。

### 3.1 所有工位都要有的

- **PP鸡 传送权限**：每个工位大号都要先手动去逍遥村的 PP鸡（传送操作员3号）那里对话一次把权限激活。
  调度员、海岸队长、收货人要用它去海岸；古井队长去花袭人买回城卷/药时也要坐 PP鸡。
- **回城卷**：至少 20 张（程序会自己补到 100 张，但第一次要有张能用）。
- **背包空位**：至少 10 格空着。
- 金币：见下表；以后不够了程序会自动从收货人那里拨。

### 3.2 每种工位的要求

| 工位 | 数量 | 等级（生产实测） | 战斗 | 开局金币 | 开局放在哪 | 备注 |
|---|---|---|---|---|---|---|
| **调度员** dispatcher | 1 | 31 级就够（不打怪） | 不需要 | **≥ 20 万**（实测带 1000 万更省心） | 逍遥村西区 | 给每个小号 500 金币、带队坐 PP鸡（每人 190）。每小时约花 4 万，回城卷消耗快（实测带了 1071 张） |
| **古井队长** well | 3 | 43–44 级 | **出战宠物要有 烈焰爆发 1504**（3 级就行）；人物技能 扫射 803 有更好，没有程序自动改普通攻击 | ≥ 2 万 | 逍遥村西区 | 带 4 个小号在阴森古井练到 11 级，每批约 6 分钟 |
| **海岸队长** coast | 6 | 41–54 级 | **出战宠物要有 烈焰爆发 1504**（2 级就行）；803 可有可无 | ≥ 2 万 | 哪里都行（程序自己坐 PP鸡 去海岸） | 带 4 个小号在平静海岸2区刷材料，每批约 12 分钟。第一次到海岸会在落点 (1152,932) 自己记录飞鞋 |
| **收货人** receiver（兼财政主管） | 1 | 44 级（不打怪） | 不需要 | **≥ 100 万**（低于 50 万不往外拨钱） | 平静海岸2区 海子旁边 (1780,1370) 最好；不在也会自己走过去 | 收料理和小号全部金币；给其他工位拨款。**背包要尽量空**：料理 99 个一格 |

**生产机实测的 9 个队长**（2026-10-20 只读）：全都没有学 803，全都靠宠物 1504，跑得很好。所以 803 不是必须的。

### 3.3 收货人背包会满

收货人每小时收约 100 个料理（99 个一格），40 格的背包大约 1.5 天收满。
总大脑每分钟那一行会显示 `收货人背包 空 N/40 格 还能收 X 个料理（约 H 小时）`；空格 ≤ 3（`factory.toml` 的 `receiver_bag_warn`）时每分钟报警一次。
一个料理都放不下时收货人**自动停收**，小号留在队列里等，不会被隔离；这时按第 10 节"换工位角色"换一个收货人（或手动把料理转走），换好后自动接着收。
程序还没有"背包满自动换人"的功能。

## 4. 准备小号号段

- 所有小号用**同一个密码**，账号名是 前缀 + 编号，例如 `mw301` … `mw430`。
- **每台电脑一个号段，绝不重叠。** 已分配：开发电脑 mw01–mw100，生产机 mw301–mw399/430。新电脑另选一段（例如 mw501 起）。
- **要多少个账号**：每个账号有 4 个角色槽。一个角色从建到删约 1.5 小时，删除后约 3.2 小时槽位才能重新用，所以一个槽大约 5 小时出一个料理。
  目标 100 个料理/小时 × 5 小时 = 500 个槽 ÷ 4 = **约 125 个账号，建议 130 个**。
  账号少了不会出错，只是"等槽位释放"时窗口会闲着，产量下降（生产机用 100 个账号时日志里有大量"槽位还没释放"）。
- 号段里的账号**事先不要有角色**（有的话那个号只用剩下的空槽，检查环境时会提示）。

## 5. 安装软件

1. 装 **Python 3.14**（python.org 下载，安装第一页**勾选 Add python.exe to PATH**）。不需要 pip 装任何东西。
2. 装 **Git for Windows**（一路默认）。
3. 把游戏目录整个复制到新电脑（约 2.4 GB），例如 `C:\什么什么大冒险2.0\`。游戏版本要是 **2.98 或 2.99**（检查环境会核对）。
4. 拉代码（在"命令提示符"里执行）：
   ```
   git clone https://github.com/GeekerYxs/roach-kitchen.git D:\roach-kitchen
   ```
   做完应该看到 `D:\roach-kitchen\batch_provision\` 里有一堆 `一键….cmd`。
5. **答题器**：游戏会不定时弹防外挂选择题，答不上队长会卡住。代码目录里的
   `大冒险2_自动答题器_原生无感关窗版\启动答题器.exe` 在游戏窗口开起来以后双击运行一次，让它一直开着（它会自动给新开的窗口注入）。

## 6. 写本机配置 `local.toml`

进入 `D:\roach-kitchen\batch_provision`，把 `local.example.toml` 复制一份改名为 `local.toml`，用记事本打开改。
模板里已经写好了 3 古井 + 6 海岸的 11 个工位，通常只要填密码、改游戏路径和号段；换了大号就改对应的 account / name：

- `[game] exe`：游戏路径（**单引号**），例如 `'C:\什么什么大冒险2.0\v2.1\win32\WaatClient.exe'`
- `[accounts]`：小号前缀、起始编号、个数、密码
- `[passwords]`：11 个工位大号的密码
- 11 个 `[[station]]`：每个工位的 id、角色、账号、第几个角色、角色名
- `[supervisor] max_windows`：小号窗口上限，32 GB 机器写 40（内存不够时程序会自己暂停）
- `[game] ip_max_clients = 50`、`ip_reserve = 2`：服务端单 IP 最多 50 个游戏窗口。小号上限会自动压到
  50 − 工位数 − 1 − 2（11 个工位时是 36），所有工具开窗口前也会数本机窗口，到 49 个就等。
  两台电脑共用一个公网 IP 时，这 50 个是两台合用的，每台填自己分到的数
- `[batch] minimize = true`、`min_free_memory_mb = 1500`

填好后大致是这样（节选，完整的看模板）：

```toml
[game]
exe = 'C:\什么什么大冒险2.0\v2.1\win32\WaatClient.exe'
server_index = 0

[accounts]
prefix = "mw"
start = 301
count = 130
digits = 2
password = "小号密码"

[passwords]
xq05 = "密码"      # 调度员
ha01 = "密码"      # 古井队长 1
xq03 = "密码"      # 古井队长 2
cap02 = "密码"     # 古井队长 3
cap07 = "密码"     # 海岸队长 1..6
cap08 = "密码"
cap09 = "密码"
cap10 = "密码"
cap11 = "密码"
cap12 = "密码"
xq02 = "密码"      # 收货人

[[station]]
id = 'dispatcher1'
role = 'dispatcher'
account = 'xq05'
slot = 1
name = '小强杀手五号'

[[station]]
id = 'well1'
role = 'well'
account = 'ha01'
slot = 1
name = '海岸女队长一号'

[[station]]
id = 'well2'
role = 'well'
account = 'xq03'
slot = 1
name = '小强杀手三号'

[[station]]
id = 'well3'
role = 'well'
account = 'cap02'
slot = 1
name = 'cap02'

[[station]]
id = 'coast1'
role = 'coast'
account = 'cap07'
slot = 1

# coast2 .. coast6 照抄上面一段，改 id / account / name

```

说明：`slot` = 这个账号的第几个角色（选角界面从左数，1–4）；`name` = 角色名，填了程序会核对没登错号；
`id` 一旦定了就别改（换人时只改 account/slot/name）。`local.toml` 含密码，不会上传 GitHub。

## 7. 第一次启动（按顺序）

| 步骤 | 双击 | 做完应该看到 |
|---|---|---|
| 1 | `一键检查环境.cmd` | 每一项都是 `[OK]` 或 `[提示]`；有 `[错误]` 先按提示改 |
| 2 | `一键建角.cmd` | 给号段里每个账号建 4 个角色（mw301r1–r4 …），8 个窗口并行，130 个号约 10 分钟。可以重复运行，只补没建成的。报告 `logs/provision_report_*.md` |
| 3 | **在其他电脑上**停掉总大脑、关掉这 11 个大号的游戏窗口 | 同一个号两边登录会互相挤 |
| 4 | `一键登录工位.cmd` | 11 个工位进游戏，窗口排在屏幕上，最后一行 `完成 11/11` |
| 5 | `启动答题器.exe`（答题器目录里） | 控制台列出所有游戏窗口 |
| 6 | `一键总大脑.cmd` | 黑窗口每分钟一行汇总（窗口数、各阶段人数、料理数）。小号窗口会陆续打开并自动最小化 |

之后就不用管了。日志在 `batch_provision\logs\supervisor_*.log`。

## 8. 日常

- **看产量**：总大脑黑窗口的汇总行，或 `logs/supervisor_*.log`。
- **停机**：在总大脑黑窗口按 `Ctrl+C`。再双击 `一键总大脑.cmd` 会接管还开着的窗口，从数据库里接着做。
- **工位掉线**：总大脑会自己关窗重登（30 秒读不到角色就判定掉线）。
- **钱**：不用管。小号交出的金币和卖杂物的钱都进收货人，收货人再拨给调度员和队长。收货人金币一直往下掉时检查一下调度员是不是在空转。
- **收货人背包**：每 1–2 天看一次（见 3.3）。
- **清日志**：`一键清空日志.cmd`（不碰数据库）。

## 9. 更新代码

开发电脑推送后，在生产机上：先停总大脑（Ctrl+C），然后在命令提示符里

```
cd /d D:\roach-kitchen
git pull
```

再双击 `一键总大脑.cmd`。`local.toml`、`state/`（数据库）、`logs/` 不受 `git pull` 影响。

## 10. 换工位角色（例如收货人背包满了）

1. 在 `local.toml` 里只改那个工位的 `account` / `slot` / `name`，**`id` 不变**（收货人一直叫 `receiver1`）；新账号密码写进 `[passwords]`。
2. 停总大脑 → 双击 `一键登录工位.cmd` → 双击 `一键总大脑.cmd`。

新收货人要有 PP鸡 权限、背包空、金币 ≥ 100 万（它是财政主管）；最好先手动把它带到海子旁边 (1780,1370)，程序会在那里记录飞鞋。
旧收货人的金币要手动交易给新收货人。历史不受影响："料理已交出"记在小号身上，不管是哪个收货人收的。

## 11. 不想在这台电脑跑了

停总大脑，关窗口，把这台电脑的号段让给下一台（或给下一台换一批新号段）。没走完流程的角色放着不管，以后可以 `一键清空小号.cmd` 删掉（约 3 小时后槽位释放）。

## 12. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 检查环境说游戏版本不对 | 游戏不是 2.98/2.99。游戏自动更新后要等开发电脑适配新版本再 `git pull` |
| 进入世界卡 40 秒报 error=110，日志"本机游戏窗口 N 个…单 IP 上限" | 窗口数到了单 IP 上限：检查 `ip_max_clients`；是不是手动多开了窗口，或另一台同 IP 的电脑也在跑 |
| 新窗口开不出来，日志"空闲内存 < 1500MB" | 内存满了：调小 `max_windows`，确认开了 `minimize`，页面文件设成 32 GB |
| 某个号一直"进入失败 error=110" | 那个角色还在"删除中"（删除后约 3 小时）或服务器没响应，程序会过一会儿再试 |
| 队长一直站着不动 | 先看是不是弹了答题框没答（答题器有没有开）；再看日志里那个工位的最后几行 |
| 某工位日志"补给失败" | 走不到商店或没钱，10 分钟后自动重试，这一批照常开工；连续出现就手动看一下那个号 |
| 想看某个号背包会被卖掉什么 | `python -m factory.items 角色名`（只读，什么都不发） |
